## 8. 问题与修复记录

### 已修复：默认不信任 XFF

限流 IP 使用 `HttpServletRequest.getRemoteAddr()`，不再读取客户端可伪造的 `X-Forwarded-For`。经过可信网关时，需要在网关层完成来源地址治理，应用层不直接信任该 Header。

### 待确认问题

1. 200 用户同机压测时所有请求可能共享同一个 `remoteAddr`，IP 限流阈值会影响正常用户场景；正式压测应使用足够高的 IP 阈值或多源地址环境，并单独记录该限制。
2. JMeter 的 token 获取和 buy 是两个采样器，报告需分别统计 token 延迟与 buy 受理延迟，不能只看总事务时间。
3. MQ 异步落库存在竞态，订单/库存断言必须在队列清空后执行，不能在最后一个 HTTP 响应后立即断言。

v3 报告最终结论待填入第 5 至第 7 节实测结果。只有在 QPS 不低于 v2、无防刷绕过、无超卖、无重复订单且库存 diff 为 0 时，才判定 v3 通过。
