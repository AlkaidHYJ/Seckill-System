## 统计口径

本节为全篇 QPS 与目标判定的统一口径，沿用 v3，先行约定。

- **主口径（buy 受理）：QPS `<待填>`**，统计 `buy/{path}` 采样器（200 样本/轮），对齐 v3 的 469.5 与 v2 的 393.7，**可直接比较**。护栏目标「≥ v3 的 90%（≥ 422）」按此口径判定。
- **次口径（端到端整体）：QPS `<待填>`**，统计每轮 400 样本（200 token + 200 buy）。因每个用户新增一次 token 往返，请求模型与 v2 不同，**仅作参考，不与 v1/v2 做达标比较**。
- **统计方式**：所有 QPS 取 JTL 时间窗 **span 口径**：`span = max(timeStamp + elapsed) - min(timeStamp)`，`QPS = 样本数 / span`；与 v2/v3 一致（v3 报告已用同一脚本对 v2 的 r2/r3/r4 复现 365.0 / 393.7 / 406.5）。
- **不作为验收口径**：JMeter Summariser 瞬时吞吐含线程启动/ramp 时间，偏低，仅作观测参考。

## 2. 测试范围

### 覆盖

- 正常用户 JWT → token/path → buy/{path}（场景 1）
- 超时取消：JOB-01 扫表 CAS 关闭 + `TIMEOUT_REFUND` 建单（场景 2）
- 库存回补：JOB-02 领取/执行/幂等（场景 2）
- 关闭与支付互斥（场景 3）
- 三方对账：JOB-03 双 diff 检出与告警（场景 4）
- 接入层修复：`accept-count` 突发建连（场景 5）
- 可观测：traceId 跨 MQ（场景 6）、慢 SQL、关键指标

### 不覆盖

- 自动修复库存（超范围，设计 17.8-9）
- 分布式事务 / 分库分表 / Prometheus + Grafana
- IP 维度限流独立实测（v3 遗留，本轮仍受同机单 IP 限制）
- `ENDED` 活动结束后的自动对账（设计 L6）
